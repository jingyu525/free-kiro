# steering-inject-to-ide — Design

## Architecture

新增 `internal/steering/inject.go` 承载"加载 + 过滤 + 组装 + 写入"
流水线；新增 `internal/cli/steering_inject.go` 注册
`free-kiro steering inject` Cobra 子命令。两层分离保证：

- `internal/steering` 只依赖 `models` / `workspace` / `errors`，
  不引入 cobra / os/exec，便于纯函数单测
- `internal/cli` 仅做 flag 解析 + 调用 steering 包 + 处理 IO

```
┌──────────────────────────────────────────────────────────┐
│ free-kiro steering inject --dry-run --only "CLAUDE.md"  │
└─────────────────┬────────────────────────────────────────┘
                  │ cobra subcommand
                  ▼
┌──────────────────────────────────────────────────────────┐
│ internal/cli/steering_inject.go                          │
│   - 解析 --dry-run / --only                              │
│   - 调用 steering.InjectAll(...)                         │
│   - 退出码处理（3 / 跳过数 / 0）                          │
└─────────────────┬────────────────────────────────────────┘
                  │
                  ▼
┌──────────────────────────────────────────────────────────┐
│ internal/steering/inject.go                              │
│   Store.InjectAll(onlyGlob) → InjectResult               │
│     1. LoadAll() → 过滤 mode==always → 按 Name 排序     │
│     2. 拼装 markdown block（标题 + body + 空行分隔）     │
│     3. 对每个目标文件：                                   │
│        a. 读文件                                          │
│        b. 定位 start/end marker（行级扫描）              │
│        c. 替换 marker 之间内容                            │
│        d. 写回（或 dry-run 时打印 stdout）               │
└──────────────────────────────────────────────────────────┘
```

## Components

| Component | Responsibility | Key API |
|---|---|---|
| `internal/steering/inject.go` | `Store.InjectAll(onlyGlob string) InjectResult` — 主入口 | 纯 IO + 文件处理，无 cobra 依赖 |
| `internal/cli/steering_inject.go` | `steeringInjectCmd() *cobra.Command` — CLI 包装 | 解析 flag / 处理退出码 |
| `internal/ide/templates/instructions_zh.md` 等模板 | 在 `## 编码规范` 段后追加 inject marker 块 | `free-kiro init` 调用 |
| 5 个项目根指令文件 | marker 块存在 → 被覆盖；不存在 → 跳过 + 警告 | 通过 `Store.InjectAll` 写回 |

## Data Model

新增 `internal/steering/inject.go` 中的核心类型：

```go
// InjectResult summarizes what happened for one InjectAll call.
// Skipped carries per-file reasons so callers (CLI) can surface them.
type InjectResult struct {
    Block      string         // 组装好的 markdown 块（注入到 marker 之间的内容）
    Written    []string       // 成功写入的文件路径（dry-run 时为空）
    Skipped    []InjectSkip   // 跳过的文件 + 原因
    DocCount   int            // 被注入的 always steering 文档数
}

type InjectSkip struct {
    Path   string // 相对项目根
    Reason string // "missing inject marker, run free-kiro init first"
}

// 硬编码的 5 个目标文件路径（与 docs/HOOKS.md §"每只写哪里" 对齐）
var DefaultInjectTargets = []string{
    "CLAUDE.md",
    "AGENTS.md",
    ".cursorrules",
    ".cursor/rules/free-kiro.md",
    ".continue/rules/free-kiro.md",
}

const (
    InjectMarkerStart = "<!-- free-kiro-managed:start -->"
    InjectMarkerEnd   = "<!-- free-kiro-managed:end -->"
    InjectBlockHeader = "<!-- auto-generated by free-kiro steering inject; do not edit -->"
)
```

marker 选用 `<!-- free-kiro-managed:start -->` / `<!-- ...:end -->` 而非
简单 `<!-- ... -->`，是为了与文件首行的 `# free-kiro-managed:` 注释
区分——前者标记"整个文件由 free-kiro 管"，后者标记"这块内容由
`steering inject` 管"。

## 注入块格式

```
<!-- free-kiro-managed:start -->
<!-- auto-generated by free-kiro steering inject; do not edit -->

## product.md
<product.md body, frontmatter 已剥离>

## structure.md
<structure.md body>

## tech.md
<tech.md body>
<!-- free-kiro-managed:end -->
```

- 文档按 `Name` 字母序（`product` → `structure` → `tech`）
- 每个文档前一行 `## <相对 .kiro/steering/ 的文件名>` 二级标题
- 文档间空行分隔
- 块前后各空一行（marker 自身独占一行）

## Marker 定位与替换策略

行级扫描（不引入正则，保持 stdlib only）：

```go
// 伪代码
startIdx := findLineContaining(content, InjectMarkerStart)
endIdx   := findLineContaining(content, InjectMarkerEnd, after=startIdx)
if startIdx == -1 || endIdx == -1 || endIdx <= startIdx {
    return InjectSkip{Reason: "missing inject marker, run free-kiro init first"}
}
newContent := lines[:startIdx+1] + blockLines + lines[endIdx:]
```

- 仅替换两个 marker 行**之间**的内容（不含 marker 本身）
- marker 行**不**被改写——避免 init 重跑时把 marker 行也覆盖
- marker 之外的所有行（包括首行 `# free-kiro-managed:`）原样保留

## Error Handling

| 场景 | 行为 | 退出码 |
|---|---|---|
| `.kiro/steering/` 不存在 / 无 `mode: always` 文档 | stderr 报错，**不写任何文件** | 3 |
| `--only` glob 语法错 | stderr 报错，**不写任何文件** | 4 |
| 单个目标文件缺 marker | 跳过该文件 + stderr 警告 + 继续 | 该次 InjectResult.Skipped 累计；最终退出码 = len(Skipped)（最多 5） |
| 单个目标文件不可写 / IO 错 | 同上：跳过 + 警告 + 继续 | 同上 |
| `--dry-run` 时任何 IO 错都不算错（不实际写） | 0 | 0 |
| 全部 5 个文件成功 | — | 0 |

`Store.InjectAll` 始终返回 `InjectResult`，**不返回 error**；CLI 层根据
`Result` 字段决定退出码。这避免了一半成功一半失败的复杂错误传播。

## Migration / Rollout

1. **不破坏现有行为**：`free-kiro steering list/show/context` 子命令保持
   不变；只是 `steering` 父命令新增第 4 个子命令 `inject`
2. **存量项目升级**：v0.8.x 的 `free-kiro init` 会自动在新写的指令文件
   模板里嵌入 marker 块；存量项目重跑 `init --overwrite-instructions`
   后再跑一次 `steering inject` 即生效
3. **回滚路径**：删除 5 个指令文件里的 marker 块（连同之间的内容）即可
   完全关闭 steering 注入；`free-kiro steering inject` 不会再写这些文件
   （marker 缺失会跳过）

## 关键决策记录

- **为什么不用 `# free-kiro-managed:` 作为 marker**：首行 marker 表示
  "整个文件由 free-kiro 管"（`init` 的语义），与"这一段由 inject 管"
  是不同概念。混用会让 init 重写时无法识别"用户手写 vs inject 注入"
  的边界
- **为什么不直接拼 markdown 到文件末尾**：每个 IDE 的 agent loader 读
  到的不一定是整个文件（如 Cursor 模块化规则按 frontmatter 触发）；
  放在 marker 块内让未来可以精细化定位
- **为什么不全量重写 5 个指令文件**：保留用户手写的硬约束段落（如
  "SessionStart 必须先 Read .kiro/steering/coding-style.md"），避免每次 inject
  把项目维护者的人工编辑也覆盖掉
