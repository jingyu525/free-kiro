# steering-inject-to-ide

把 `.kiro/steering/*.md` 中 `mode: always` 的内容自动拼装成 markdown 块，
注入到 IDE agent loader 会主动读取的项目根指令文件（`CLAUDE.md` /
`AGENTS.md` / `.cursorrules` / `.cursor/rules/free-kiro.md` /
`.continue/rules/free-kiro.md`）的指定 marker 区域内。让 Claude Code /
CodeBuddy / Cursor / Continue / OpenCode 在会话开始时自动看到项目级
steering 约定，而不是只服务于 free-kiro CLI 进程内部。

## User Stories

- As a free-kiro 用户 I want `.kiro/steering/*.md` 的 always 内容自动出现在 Claude Code / CodeBuddy 的项目根指令文件中 so that 我不用每次手动把 steering 内容粘到 CLAUDE.md / AGENTS.md 里，agent 也能看到项目约定。

## Acceptance Criteria

- [AC-1] WHEN 用户执行 `free-kiro steering inject` THE SYSTEM SHALL 在 1 次调用内把 `.kiro/steering/*.md` 中 mode: always 的文档按文件名字母序拼成 1 个 markdown 块，写入项目根 5 个 IDE 指令文件的 marker 区域内，且 5 个文件全部成功写入时进程以退出码 0 结束。
- [AC-2] WHEN 用户执行 `free-kiro steering inject --dry-run` THE SYSTEM SHALL 在 1 次调用内把将注入的内容打印到 stdout（至少 1 行），不修改任何文件，进程以退出码 0 结束。
- [AC-3] WHEN 任一目标指令文件中 inject marker 块缺失（start/end 配对缺失或不匹配）THE SYSTEM SHALL 跳过该文件、向 stderr 输出 1 条警告（含 path），继续处理其余文件，最终进程以退出码 0 结束（skipped 不影响 exit code，由 stderr warning 即可表达）。
- [AC-4] WHERE 用户传 `--only <glob>` THE SYSTEM SHALL 只处理路径匹配 glob 的目标文件，glob 语法支持 2 种通配符（`*` 与 `?`），不接受 `**`，匹配命中数在 0 到 5 之间。
- [AC-5] UNLESS 用户传 `--only` 指定具体子集 THE SYSTEM SHALL 默认处理 5 个目标文件（CLAUDE.md、AGENTS.md、.cursorrules、.cursor/rules/free-kiro.md、.continue/rules/free-kiro.md）。
- [AC-6] WHEN `.kiro/steering/` 目录不存在或目录内没有 mode: always 的文档 THE SYSTEM SHALL 在 100ms 内报错退出，stderr 输出 1 行错误消息（含路径），进程以退出码 3 结束，且 0 个 IDE 指令文件被修改。
- [AC-7] WHEN `--only` 的 glob 语法非法（含 `**` 或未闭合字符类）THE SYSTEM SHALL 在 50ms 内报错退出，stderr 输出 1 行错误消息（含 pattern），进程以退出码 4 结束，且 0 个 IDE 指令文件被修改。
- [AC-8] THE SYSTEM SHALL 在注入块首行写入 1 条 `<!-- auto-generated by free-kiro steering inject; do not edit -->` 注释，且在 marker 内每个原 steering 文档前写入 1 个 `## <相对 .kiro/steering/ 的文件名>` 二级标题，文档间用 1 个空行分隔。
- [AC-9] THE SYSTEM SHALL 在 1 次 inject 调用中保留 marker 块外的全部内容（包括首行 `# free-kiro-managed:` 注释与后续手写段落）不被修改，且 start/end marker 行本身不被改写。
- [AC-10] THE SYSTEM SHALL 在 1 次 inject 调用中只从 mode: always 的 steering 文档生成注入块，mode 为 auto / manual / filematch 的 0 个文档进入注入块。

## Out of Scope

- 不做 SessionStart / PreToolUse hook 的"自动触发 inject"集成（依赖 Claude Code 等 IDE 的 hook 能否把 stdout 注入 system prompt，机制未确认；用户可手动跑或接 git hook）。
- 不做 watch 模式下的实时重新注入（v0.8.x 不在范围）。
- 不改动 `.kiro/AGENTS.md` 的语义 —— 该文件继续仅由 `internal/steering/store.go` 的 steering store 加载，不进 IDE 指令文件。
- 不在注入内容里包含 `mode: auto` / `manual` / `filematch` 的 steering 文档（这些需要 prompt 关键词或显式引用，不适合 always 注入）。
