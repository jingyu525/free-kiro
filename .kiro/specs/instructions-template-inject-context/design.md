# instructions-template-inject-context — Design

## Architecture

纯模板内容变更：修改 2 个静态 markdown 模板文件，**不**改 Go 代码、
不改 `prependMarker`、不改 init IO 流程。结构与同源 spec
`.kiro/specs/agents-template-coding-standards/` 完全一致。

```
internal/ide/templates/instructions_zh.md   ← 插入中文"## 项目上下文"段
internal/ide/templates/instructions_en.md   ← 插入英文"## Project context"段
                       │
                       ▼ init --ide claude-code / cursor 写项目根指令文件
       CLAUDE.md / .cursorrules / .cursor/rules/free-kiro.md
```

## 插入位置

两个模板都在**同一位置**插入：

```
当前顺序                                 插入后顺序
─────────────────────────               ─────────────────────────
[frontmatter `mode: manual`]            [frontmatter `mode: manual`]
# free-kiro-managed:                     # free-kiro-managed:
# CLAUDE.md / .cursorrules / ...        # CLAUDE.md / .cursorrules / ...
本项目使用 **free-kiro** ...             本项目使用 **free-kiro** ...
## free-kiro 在这个项目做什么            ## free-kiro 在这个项目做什么
## 每个工具调用前（除 Read）             ## 每个工具调用前（除 Read）
## 编码规范（SessionStart 必须先 Read）  ## 项目上下文（自动注入的 steering）  ← 新增
                                        ## 编码规范（SessionStart 必须先 Read）
## 每次 Edit / Write 之前                ## 每次 Edit / Write 之前
## 完成实现时                             ## 完成实现时
## 帮助                                  ## 帮助
[marker 块]                              [marker 块]
```

新段插在"## 编码规范"之前，让 agent 按"项目背景 → 工具调用流程 →
项目上下文（解释下面 marker 块）→ 编码规范（硬约束）→ 完成实现 →
帮助"的递进顺序读。

## 模板内容

**instructions_zh.md（中文版）**：

```markdown
## 项目上下文（自动注入的 steering）

本文件末尾由 `<!-- free-kiro-managed:start -->` /
`<!-- free-kiro-managed:end -->` marker 包裹的 markdown 块，由
`free-kiro steering inject` 在每次 `init` / `inject` 运行时自动生成，
内容来自 `.kiro/steering/*.md` 中 `mode: always` 的文档（当前为
`product.md` / `structure.md` / `tech.md`）。

**这段内容不是用户手写的**——它是项目级 steering store 的 always 模式
快照。若要修改，请编辑 `.kiro/steering/<name>.md` 后跑
`free-kiro steering inject`（或 `free-kiro init --ide auto
--overwrite-instructions`）同步到这里。详见 `docs/STEERING.md`
§"自动注入到 IDE 指令文件"。
```

**instructions_en.md（英文版，结构对齐）**：

```markdown
## Project context (auto-injected steering)

The markdown block at the end of this file, wrapped by
`<!-- free-kiro-managed:start -->` / `<!-- free-kiro-managed:end -->`
markers, is auto-generated by `free-kiro steering inject` on every
`init` / `inject` run. Its content comes from the `mode: always`
documents in `.kiro/steering/*.md` (currently `product.md` /
`structure.md` / `tech.md`).

**This block is not hand-written** — it is the always-mode snapshot
of the project-level steering store. To modify it, edit
`.kiro/steering/<name>.md` and re-run `free-kiro steering inject`
(or `free-kiro init --ide auto --overwrite-instructions`) to sync
here. See `docs/STEERING.md` §"自动注入到 IDE 指令文件".
```

## 关键决策记录

- **为什么插在"## 编码规范"之前**：agent 读 CLAUDE.md 时，
  先知道下面有自动注入的 steering block，再读硬约束，符合
  "background → local context → hard rules"的阅读顺序。
- **为什么是"`## ` 二级标题"而非引用块**：与其他段对齐；
  marker 行本身是 HTML 注释（`<!-- -->`），不会与 markdown 标题冲突。
- **为什么列出 3 个 always 文档名**：让 agent 立即知道 marker 块
  里能找到什么，不需要先翻 `.kiro/steering/` 目录。
- **为什么不复制 docs/STEERING.md 的章节标题**：那是英文 + 中文混合
  的二级标题 "## 自动注入到 IDE 指令文件"，不便嵌入英文版模板；
  这里改用 `§"自动注入到 IDE 指令文件"` 作为引用指针，避免重复。
- **范围与 agents_*.md 的关系**：本 spec 与
  `agents-template-coding-standards/` 是平行实现，**不**互相依赖。
  4 个 init 模板分两批固化两段不同的内容（agents 模板加硬约束段，
  instructions 模板加项目上下文段）。

## 验证策略

1. **Lint**：`go test ./internal/ide/...` 确认现有测试不破坏
2. **Round-trip**：跑 `free-kiro init --ide auto --overwrite-instructions`
   后 `diff` 项目根 CLAUDE.md，确认含"## 项目上下文"段
3. **行数核对**：`wc -l CLAUDE.md` 对比插入前后（应增加 ≥ 10 行）
4. **marker 块位置**：grep 确认 marker 块仍在文件最后 5 行内
5. **英文版对称**：人工 review instructions_en.md 与 instructions_zh.md
   结构对齐（段标题 / marker 链接数 / always 文档列表）

## 风险与回滚

- 风险 1：英文版措辞与中文版语义有出入 → 中文版是 source of truth，
  英文版仅 fallback；agent 在 en locale 下若看不懂会主动跳到
  docs/STEERING.md
- 风险 2：CLAUDE.md 总行数继续膨胀 → 当前每个文件 ~208 行（模板 +
  inject 块），加 12 行后 ~220 行，仍在可读范围内
- 回滚：`git revert` 本 commit 即可恢复模板到精简版本
